# CSI 数据采集方案 v1（正式规范采集）

目标：为 v1 二分类模型（**motion 有移动 / idle 无移动**）建立标注数据集。
工具：Web 控制台（采集卡片）；看曲线用官方 visualizer（两者不同时开，流独占）。

---

## 一、标签体系

| 标签 | 含义 | 归入 | 用途 |
|---|---|---|---|
| `empty` | 房间完全无人 | idle | 噪声地板基线（**最重要，量要够**） |
| `static` | 有人在但静止 | idle | 「有人/无人」升级版的基础数据 |
| `walk` | 走动 | motion | 核心动作 |
| `typing` | 敲键盘 | motion | 小动作下限（灵敏度测试） |
| `page_turning` | 翻书 | motion | 小动作下限 |
| `fan` | 风扇运行 | idle | 干扰源（防误报，与人体动作区分） |

> static 归 idle 是第一版设计；若实验发现呼吸/小动作被误判为 motion，
> 后续把 static 拆出做三分类（合作方 README 已预留此迭代方向）。

## 二、采集矩阵

| 标签 | 段数 × 时长 | 位置/姿态变化 | 备注 |
|---|---|---|---|
| empty | **5 段 × 60s** | 设备位置固定 | 分不同时段采（早/晚各几段），基线要够长 |
| static | 5 段 × 30s | 距设备 1m/2m/3m，坐+站 | 正常呼吸、别刻意屏气（真实场景就是有静息体动） |
| walk | 5 段 × 30s | 1m 往返 / 2m 往返 / 3m / 隔墙 / 斜穿 | 每段保持单一距离与路线 |
| typing | 5 段 × 30s | 1m/2m，正对 + 背对设备 | 正常打字节奏 |
| page_turning | 5 段 × 30s | 1m/2m | 每 2~3 秒翻一页，节奏稳定 |
| fan | 3 段 × 60s | 风扇放设备 1m 内 | 低/中/高档各一段 |

合计：净采集 ≈ **16.5 分钟**，加切换准备 ≈ 40~50 分钟工作量。
按观察实验结果可调整：若某距离观察为「无反应」，该距离的 walk 段可少采或去掉。

## 三、每段执行纪律（直接决定模型上限）

1. **动作段要干净**：walk 段就全程走动；想休息就停下、等下一段再采
2. **段间至少隔 10 秒**，让信道回到稳态再开始下一段
3. **采集时关掉官方 visualizer 页面**（CSI 流同时只能一个会话）
4. **房间 2.4 GHz 干扰最小**：微波炉、蓝牙音箱、无线耳机全部关闭
5. **description 字段写清楚**：距离、朝向、动作幅度
   （如「1米往返 正常步速」「2米 背对设备 打字」）
6. **采完每段看丢帧**：控制台事件日志 / meta.json；pps 长期低于 90
   或 stream_gaps > 0 的会话 → 标记重采
7. **训练/测试按会话划分**：同一段数据不能既进训练集又进测试集

## 四、推荐执行顺序（3 轮）

| 轮次 | 内容 | 轮后动作 |
|---|---|---|
| 第 1 轮 | empty ×5 + static ×5 | 跑 `train.py` 看 idle 侧基线是否可分 |
| 第 2 轮 | walk ×5 + typing ×5 | 跑 train.py，验证二分类准确率 |
| 第 3 轮 | page_turning ×5 + fan ×3 | 最终训练 + 评测报告 |

每轮结束都跑一次 `python scripts/train.py --data data --out models/detector.joblib`，
用验证集准确率说话，再决定补采哪类。

## 五、每类「合格曲线」长什么样（采集前先对照）

在官方 visualizer / 控制台判断数据是否合格：

| 标签 | 曲线特征 | 不合格信号 |
|---|---|---|
| empty | 全部子载波近似平直细线，噪声 < ±2 | 周期性起伏、大台阶（说明有人或干扰） |
| static | 整体平直，允许呼吸引起的极缓慢小起伏（周期 4~8s） | 频繁毛刺（人其实动了） |
| walk | 明显起伏/台阶（> ±5），瀑布图亮带 | 全程平直（人没动或链路断了） |
| typing | 弱于 walk 的短促毛刺，幅度中等 | 与 empty 无差别（灵敏度不够，记入观察） |
| page_turning | 与翻页节奏同步的周期性小台阶 | 无节奏、杂乱（动作不干净） |
| fan | 与扇叶频率同步的稳定振荡，幅度可能很大 | 无周期性（扇叶停了） |

## 六、验收标准（何时算采完）

- 每类 ≥ 5 段干净会话（empty 5 段 × 60s 达标）
- 平均 pps ≥ 90，所有会话 stream_gaps = 0
- 会话级划分后验证集准确率 ≥ 90%，否则按评测报告补采
- 数据量估算：16.5 min × 100 pps ≈ 10 万包，npz 约 25 MB

## 附：单段操作清单（照做）

```
□ 关掉官方 visualizer 页面
□ 打开控制台 http://127.0.0.1:8000，确认设备已连接、曲线在动
□ 采集卡片：label 按矩阵填，时长按矩阵填，description 写距离/朝向/幅度
□ 点「开始采集」→ 立即就位做动作（empty 段则是立即离开房间）
□ 时长结束 → 事件日志确认「采集完成」
□ 检查 meta.json：packets ≈ 时长×100、stream_gaps = 0
□ 不满意 → 立刻重采该段
```
